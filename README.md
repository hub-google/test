# SeatFlow — 訂位／候位營運互動示範

> 原創 UI 與互動邏輯。**非 inline 官方網站**，未使用或重發 inline 的 HTML、CSS、JavaScript、商標、圖片、資料庫或非公開 API。使用 inline 公開產品資料作為功能研究參考，並獨立實作下列可操作的示範流程。

## 網站網址

官網首頁：<https://hub-google.github.io/test/>　

互動功能體驗：<https://hub-google.github.io/test/demo.html#/home>

**尚需啟用 GitHub Pages**：請至 [Settings → Pages](https://github.com/hub-google/test/settings/pages)，將 **Build and deployment → Source** 設為 **Deploy from a branch**，選 **main** 與 **/(root)**，再按 **Save**。啟用後網站會直接從 main 的靜態檔案發布，此步驟需要儲存庫管理權限。

## 可操作的功能

| 模組 | 使用者情境 | 狀態 |
|---|---|---|
| 首頁／餐廳探索 | 查看三家虛構餐廳、搜尋、切換店家 | 本機可操作 |
| 線上訂位 | 選擇日期、人數、時段，容量檢查，登記訂位 | 本機可操作 |
| 我的訂位 | 以示範手機查詢、取消訂位 | 本機可操作 |
| 現場候位 | 登記顧客、禁止同店同日重複有效取號 | 本機可操作 |
| 叫號看板 | 呈現最新叫號與後續候位、跨分頁同步 | 本機可操作 |
| 店家訂位管理 | 確認、編輯、安排桌號、取消、狀態調整 | 本機可操作 |
| 店家候位管理 | 叫下一組、重叫、過號、入座、完成、恢復 | 本機可操作 |
| 桌位圖 | 選擇空桌指派訂位、解除桌位指派 | 本機可操作 |
| 顧客 CRM | 根據手機去重、設 VIP、服務備註 | 本機可操作 |
| 餐點訂單 | 選品項、建立訂單、備餐與完成 | 本機可操作 |
| 營運報表 | 最近七天訂位、候位與訂單額統計 | 本機可操作 |
| 商家設定 | 修改店名、營業區域、時段、容量 | 本機可操作 |

### 快速驗收

1. 開啟「線上訂位」，選擇餐廳、日期、人數和時段，填入**測試**姓名與手機，建立訂位。
2. 切到「店家後台 → 訂位管理」，找到剛才的訂位，確認或更改狀態，再到「桌位圖」指定桌號。
3. 開啟「現場候位」登記兩組測試號碼，回「候位管理」點叫下一組，再到「候位看板」確認號碼有變。
4. 在「顧客管理」設 VIP、輸入服務備註，切換頁面後重新回來確認保留。
5. 在「訂單管理」新增測試餐點，依序變更為製作中、已完成。
6. 在「商家設定」更改時段或容量，再返回預約頁面確認生效。
7. 同一瀏覽器開兩個分頁，確認操作後另一分頁會更新資料。

## 明確限制

- **不是完整 inline 複製版，也不是可正式營運的 SaaS**。目前僅是功能體驗站。
- 資料只儲存於目前瀏覽器的 localStorage；跨裝置、跨瀏覽器不可共用，也沒有管理員身分驗證。
- 不會呼叫 inline、LINE、Supabase、Google Maps、簡訊、Email 或金流 API。
- 不會真的替任何餐廳建立訂位或收費。
- 僅供使用者研究公開可觀察的產品流程、對照 UI 與驗證互動規則。**請勿輸入真實個資。**
- 本頁的桌位、報表、餐點、商家資訊及部分業務規則是獨立設計的示範行為，不代表 inline 私有系統的真實實作。

## 技術

純 HTML、CSS、JavaScript，無第三方套件，支援手機、平板、桌機。根目錄是企業官網型展示頁（index.html、marketing.css、marketing.js）；原有功能體驗保留在 demo.html，透過 hash route 瀏覽。公開網站所提供的前端原始碼仍能被使用者查看，符合靜態網頁的正常運作方式。
